# PACI-FLR 原规则—修订—采纳状态对照

2026-11-05。以下保留主指令06–09章的逐条规则差异，原v0.1全文在inputs内可追溯。它不代表修订Profile正式发布。

本轮落地：8个准备性比率的缺值/零分母/单月同场所/单位检查、共同依赖、事项open/explained/remediating与资料不足并列显示。

未落地：H1–H7正式适用性、P1–P7校准、C1–C3筛查、E解释审核及resolved关闭标准。公式的当前单月实现不是完整累计期间、滚动窗口或独立基准。无H/P自动劳动违法结论。

审议状态：原文“硬规则不接受豁免”“新月正常即可通过整改”“remediating归入无异常”“C1确认产量真实”等不作为生产结论执行；保存原条款，依据主指令防误述要求暂停相关强输出，等待规则窗口正式采纳/校准。

差异影响：不能输出个体工资合规、真实产量、独立佐证或全面无异常；增加人工复核和真实补证需求。编号、旧版本与历史事项不删除。

## 06. 交叉核查：保留R1—R6，先把口径做对

【承接】原稿为六组比率、共八个指标，按月计算并保存3个月滚动统计。下表列出原公式与待落实修订；不得把原稿的异常解释自动当成现实事实。[S2，第3—4页]

| 代码 | 原公式／指标 | 必须补充的条件与解释 |
| --- | --- | --- |
| R1 | si_headcount / roster_headcount | 同一人员范围、缴纳主体、统计时点；差异待解释，不直接等同违法未参保 |
| R2 | payroll_headcount / roster_headcount | 同期同范围，处理分批支付、非银行方式、代发主体；不能将差异直接说成隐藏用工 |
| R3 | output_qty / roster_headcount | 统一工厂、工序、产品与人员口径；自动化、外包及人员月度平均需记录 |
| R4 | revenue × 12 / 月数 / roster_headcount | 明确期间累计营收还是单月营收；期间营收匹配同期间平均人数；贸易营收与自产区分 |
| R5a | payroll_total / payroll_headcount | 企业级均值筛查，不可证明每个员工达到适用最低工资 |
| R5b | payroll_total / revenue | 同期间同组织的工资与营收口径；现金支付给职工不直接等于同口径工资成本 |
| R6a | kwh_monthly / roster_headcount | 确认电表、场所、共用负载、工序、自动化及人员范围 |
| R6b | kwh_monthly / output_qty | 同一生产范围、产品可比性；比率正常不证明用电和产量各自真实 |

分母为零或缺失时不计算该比率，显示资料不足；不自动生成劳动违法flag。异常输入可以单独生成数据质量待办。单位相同只是必要条件之一，“件”相同不意味着产品可比；单位转换必须有依据，不确定则不合并。

【工程补充】冻结计算输入版本、精度与舍入、滚动窗口、时区和缺月处理；不为缺月填零；需要加权时固定方法。原始来源范围沿派生链取交集，不同有效来源可形成并集；派生摘要不得扩大原件覆盖的工厂、人员、期间或产品。

### 06.1 C1—C3组合信号修订

| 编号 | 原稿推断 | 修订建议 |
| --- | --- | --- |
| C1 | R3/R4高且R6b正常 → 产量真实、人数可疑 | 改为“组合关系需解释”；用电和产量同时填大仍可保持比率，不能确认产量真实 |
| C2 | R5a低且R1/R2低 → 工资与用工可疑 | 保留组合筛查，先核对口径与共同来源；不增加独立证据数量 |
| C3 | 合同工资／工时与均值或制度不同 → 可能篡改 | 改为同对象同期间的材料差异；篡改须有可信旧承诺、签名或具体证据 |

R3、R4、R6a共用人数分母，一次错填可同时触发多项；不得把相关指标当作三个独立佐证。保留输入依赖关系，页面能展开“哪些数据共同导致此提示”。

## 07. H/P/E规则的完整修订对照

### 07.1 H类：保留编号，修订适用性

| 编号 | v0.1原条件 | 开发处理要求／修订建议 |
| --- | --- | --- |
| H1 | R5a低于当地最低工资即红 | R5a只作均值筛查；个体判断需适用地区、期间、就业及工资口径。在授权环境计算疑似人数、已评估人数及未知人数，默认不上传全员明细 |
| H2 | 合同／制度月加班>36小时；R3>p90升红 | 36小时为原稿法源示例，先核对实际制度及适用条件；合同表述与实际工时分开。删除“产量高确认超时”的自动升级 |
| H3 | R1<0.90黄、<0.80红 | 标为初始筛查阈值，非法律容忍比例；核对社保及名册范围，允许适用性异议 |
| H4 | R2<0.90黄、<0.80红 | 标为初始筛查阈值；核对支付方式、代发批次、支付主体与人员范围 |
| H5 | 合同样本与R5a／制度偏差>15% | 改为同一对象、期间、口径的冲突；个人合同工资与全公司均值不同不自动异常。15%未正式校准 |
| H6 | 押金、扣证件、限制离职条款AI识别即红 | 高优先级语义线索，附原文及上下文；处理否定与引用。标记模型发现／人工复核，不自动裁定事实与违法 |
| H7 | 确认后修改无理由即黄 | 写入时要求追加版本与理由，拒绝无痕覆盖；被拒绝的修改尝试按安全策略留痕，不自动归责蓄意造假 |

H类也允许提出规则不适用、识别错误、范围错误和事实纠正。允许纠错不等于豁免法律。强迫劳动相关评估还应区分非自愿性、惩罚威胁、离职自由、招聘债务、证件控制等事实；仅工资与生产比率正常，不能表示这些事实已经排除。

### 07.2 P类：保留全部初始阈值，但不得当作已验证法则

| 编号 | 指标 | 原黄／红阈值 | 首期处理 |
| --- | --- | --- | --- |
| P1 | R3人均产量偏高 | >p90 / >p95 | 基准可比性成立后试验；不直接推断超时或隐工 |
| P2 | R4人均营收偏高 | >p90 / >p95 | 区分集团、工厂、贸易与自产 |
| P3 | R5a人均工资偏低 | <p10 / <p5 | 与法定个人工资判断分开 |
| P4 | R5b工资营收比偏低 | <p10 / <p5 | 先统一财务及人群口径 |
| P5 | R6a人均用电偏高 | >p90 / >p95 | 纳入工序、电表和自动化范围 |
| P6 | R6b单位产量用电 | <p10或>p90 / <p5或>p95 | 产品可比性不足时不运行 |
| P7 | C1或C2 | 触发即红 | 建议取消自动“即红”；显示共同输入、独立证据及复核优先级 |

“连续两个月才开flag”只可用于适合观察趋势的规则；不能延迟记录当次提取冲突、签名失败、篡改检测或重要条款线索。单月越界、规则未运行和当前已开flag须分别显示。

### 07.3 E类说明与X1挑战

保留E1自动化（设备或产线佐证）、E2外包（外包合同及有权访问的相关证据）、E3季节性（足够期间数据）、E4产品结构不同（产品及结构信息）、E5贸易型营收（采购等依据）、E9其他说明。它们是“解释候选”，不是输入代码就自动豁免。外包可能解释比率，但不能把相关外包工序从任务范围中抹掉。

保留X1外部挑战。挑战是具体、可追踪的异议，不等于已确认造假；受控私密记录的挑战保持原披露边界。企业普通回应、说明审核与独立争议裁决各自有权限及结果，不共享一个“已解决”按钮。

## 08. 行业基准与维护政策

【承接】原稿回退顺序：四位行业码＋省＋规模 → 三位码＋省＋规模 → 三位码＋全国＋规模 → 二位码＋全国；不足n=30则不作同行flag。规模档为<50、50—299、300—999、≥1000。保留为试验设定，不宣称已验证。[S2，第4页]

候选数据为上市公司年报、官方统计、当地最低工资来源及有适当授权的用户汇总。公开均值不能生成不存在的p90/p95；集团年报不能直接比较单一工厂；年度现金支出不能直接当作月度代发工资；同一企业多个月不是多家独立企业。

【修订建议】优先同企业历史变化，同行基准先内部观察。n≥30不能单独保证尾部分位可靠；回退不能跨越产品与口径的不相容。样本不足显示“无可用基准”，不强凑排名。

每次基准记录版本、来源、样本单位及独立数、行业／区域／规模、数据定义、期间、清洗方法、分位方法和更新时间。原稿“剔除所有未解决红flag企业”应修订：数据质量剔除与风险标签分开，记录排除理由与敏感性比较，防止模型用自己标签定义正常。

用户数据不得默认进入共享基准；记录授权与退出处理。n<5不显示分位是原稿最低保护设想，不等于达到5家就保证匿名。控制重复查询、组合筛选和历史差分的反推风险。重跑判定所需的基准数值快照应对获准核验者可用，只有哈希不能重算；无需公开企业原始贡献数据。

最低工资、4个月更新提醒、24个月历史展示、90天删除等待、5工作日审阅、60／90天整改等，均须分类为法源条件或产品建议。不能将产品时限显示为法律宽限期；不在没有复核团队时承诺固定人工响应SLA。

## 09. Flag生命周期、独立争议与防洗白

### 09.1 保留四态，但明确关闭依据

| 状态 | 真实含义 | 不得显示成 |
| --- | --- | --- |
| open | 待处理的发现或异议 | 已确认违法 |
| explained | 企业已提交说明，尚待适当审核 | 说明已被接受、问题已解决 |
| remediating | 整改正在进行或等待复查 | 已整改完成 |
| resolved | 满足指定关闭条件，记录理由及复核依据 | 历史从未存在问题 |

【工程补充】resolved增加关闭原因，例如误报纠正、适用性解释成立、实际整改完成；名称为建议，最终由Profile契约确定。不得删除旧flag；复发建立新flag并关联旧项。外部挑战撤回不等于争议事实已被裁决。

关闭实际用工问题需要实际行动与结果证据。下一月某个比率恢复正常，不足以证明此前欠付或损害已补救。没有独立复核人不阻断企业补件与纠错，但不输出“独立裁决成立／驳回”等结果。

### 09.2 重写公开总体状态

第6页原状态机将explained标为待人工审阅；第7页“无异常”条件遗漏remediating，且没有完整覆盖资料不足及未满30天的黄色open。不得照搬这组逻辑。[S2，第6—7页图及表]

| 展示摘要 | 形成条件 |
| --- | --- |
| 存在未解决事项 | 存在open、待审explained或remediating；严重程度和处理阶段另列 |
| 历史事项已完成复核 | 相应问题均满足关闭条件，保留关闭原因和受控历史 |
| 在已检查范围内未发现异常 | 必要输入与适用检查已完成，无相关未解决事项；同时显示检查范围 |
| 资料不足／部分范围未评估 | 缺必要输入、来源不可见或不满足适用条件；不能当作绿灯 |

这些是摘要展示维度，不是互相吞并的唯一状态：已知严重问题与资料缺口可以同时存在。部分资料缺失不能遮盖已知问题，历史问题解决不能意味着未评估部分正常。

### 09.3 发布与历史

预检默认私有，企业可选择不对外发布；不得发布隐瞒所声明范围内重大未决反证的“干净结论”。敏感事项可缩小声明、提示无法确认或转受限专业复核，不以“防洗白”为理由强制公开所有私人资料。

固定签核卡片保持不变；实时状态栏在既有授权范围内提示新版本、待处理挑战、撤回或更新需要。撤回后重发不能清除历史，也不能通过重新注册卡片绕开关联。旧授权不自动开放新原件、新页码、新买家或新用途。
