## 实际交付

- `/conversations` 为正常登录的独立会话页。侧栏、欧盟入口页、内嵌对话都可进入；不增加首页主功能面板。列表只包含当前账号已经开始的双边会话，不公布联系人目录、对方第三方关系、私有任务用途或消息正文摘要。
- 会话列表从原已兑换双方关系查询，不使用过滤已撤销/到期材料授权的buyerList。材料授权停止后历史沟通仍可见，列表明确材料权限是否有效。发送普通消息沿用既有对话关系，不能凭此读取材料。
- 未读按持久化消息sequence和本人last_read_sequence计算，本人发送不计未读。打开列表/会话不自动标读；用户明确将实际加载的最后一条消息及此前标读。标读并发期间新消息仍保持未读；旧标读请求不会降低已读位置。不向对方提供已读回执，也不把未读清零等同接受合规提交。
- 站内提醒由刷新查询持久记录计算，非邮件或实时推送。线程每次加载最近100条，按单调序号加载更早消息；相同时间戳不再由随机ID决定新消息先后。
- 消息可附同一grant的固定已发布卡引用，UI从实际获准版本选择。只存evidence_sequence/evidence_card_id；线程/列表不复制投影正文或私密材料。未发布版本、另一授权、非法序号拒绝。旧引用不会跟随后续发布改变。
- 发送引用在同一事务检查授权有效与会话可写，并分配消息序号。撤权竞争回滚，不留下额外未读或半条消息。发送成功或收到引用不计买方证据查看。
- 实际打开/下载引用时重新鉴权。买方走BuyerAccessStore的日志和最终授权检查；所有者只取得同一获准投影，不调用私密exportCard，不借买方身份制造VIEWED统计。供应方在此引用通道也要求材料授权仍有效；其自身私密任务访问仍是另一条现有路径。
- 引用卡显示材料范围、覆盖/企业确认与检查状态、获准参数及事项数量；下载HTML仍为可读历史副本。撤权不能删除已经阅读或下载的内容，刷新/新下载继续检查最新授权。
- 同键不同内容并发发送现在明确返回IDEMPOTENCY_CONFLICT，不再将数据库唯一键冲突当通用503。

## 数据迁移

0010_right_puck新增conversation_reads；消息新增sequence/evidence_sequence/evidence_card_id；会话新增last_sequence。旧消息按既有(created_at,id)顺序回填sequence，再创建唯一索引并同步会话头。已有正文/幂等摘要保持不变；旧消息没有引用，初始未读位置为0。不改写既有卡片哈希或原授权时效。

## API

GET /api/conversations 无grant：本人会话及unread_total。
GET ?grant=...：线程最新100条；可选before为独占上界。
POST action=mark_read：grant_id、through_message_id，仅标至该会话内实际消息位置，单调幂等。
POST action=send：原数据可选evidence_sequence，参考原授权已发布版本。
GET ?grant=...&reference=message_id：按该条消息固定引用重新鉴权；format=html下载同版卡。
所有读写用正常Sites账号，响应private/no-store，POST保留readDemoCommand来源/请求约束；不使用伪造账号头进行生产验收。
