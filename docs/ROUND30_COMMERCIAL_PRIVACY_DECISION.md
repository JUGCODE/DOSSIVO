## Access logs: explicit acceptance boundary

Owner must be able to inspect authenticated account, server UTC time, requested card version, grant and event type; revoked/expired grants retain appropriate historical records. No raw evidence, prices, access-code secrets, unrelated contacts or other buyer relationships in the log response. Requests reauthenticate; log retrieval is owner-scoped, paginated and private/no-store. Account ID is not a verified legal entity/person. VIEWED/DOWNLOADED mean successfully processed server requests, not confirmed human reading or file retention. Anonymous access cannot be attributed to a known person. Failed attempts, support access, original-file events and full organisation export need separate coverage; never call the current card log complete platform auditing.
