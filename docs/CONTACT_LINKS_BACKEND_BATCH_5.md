# 第5批 · 联系ID、链接与独立通信后台 · 2026-11-05

用户明确要求实现可点击联系ID/链接，并完成后台；原直接通信侧栏图标改双人。承接Site第31版，本批不改原宪章，不另建站点或PACI内核。

## 实际交付

1. 正常登录用户主动创建测试显示名称和联系设置，后台生成随机96位DS-公共ID，账号内稳定；不从登录邮箱/真实姓名自动生成公开名称。允许修改显示名或关闭发现。关闭后新的精确ID查询/公开联系预览不可用；已有联系人/申请不被抹除。
2. 可复制ID、同源联系链接和二维码；二维码在客户端本地生成，不把ID/链接发往第三方二维码服务。手动查询仅精确ID，不支持邮箱、前缀或目录枚举。公开页面只展示主动开放的显示名/ID；个人账号与企业代表资格并不等同。
3. `/connect/[publicId]`为真实服务端联系落地页。未知/未开放/不匹配推荐链接统一不可用。登录链接用规范化ID和已核验推荐token构造同源安全return_to，保留原目标；访问/登录不会自动申请或接受。
4. 联系申请由服务端从ID解析真实接收账号，记录PENDING；接收方可ACCEPT/DECLINE。只有接收方可以处理，发送方及第三方不能代为接受。同一双方唯一申请，双向/并发不自动接受；拒绝后不由新key静默重新打开。后续可设计明确的撤回/重新申请流程，当前没有该入口。
5. 接受后创建独立联系人关系，`dm_`会话用contact_id，不写入材料授权表；会话表CHECK要求grant_id/contact_id恰好一个非空。双方可进行文字请求、普通消息、关联回复、确认收到，使用既有持久消息序号、未读、分页、幂等。联系人会话没有卡片引用权限，材料要走既有独立授权流程。
6. 双方各自有屏蔽位。只能改自己的屏蔽；任一方屏蔽即阻断新消息，另一方不能代为解除。发送事务重验屏蔽，包括绕回同一双方的旧材料授权会话；历史消息可读。屏蔽通信本身不撤销独立材料授权。
7. 已接受且双方未屏蔽、均主动开放的联系人可以分享推荐链接。推荐token由后台记录真实分享账号及目标；链接预览和申请列表显示“由某人分享此联系人”。不接受客户端随填推荐人。生成/使用推荐遇到并发屏蔽或关闭发现时事务回滚，旧token不再解析；不能将推荐称身份认证或尽调背书。
8. 侧栏直接通信使用UsersRound双人图标，欧盟入口继续使用UserRoundCheck单人图标；共享页没有欧盟用户专属导航。
