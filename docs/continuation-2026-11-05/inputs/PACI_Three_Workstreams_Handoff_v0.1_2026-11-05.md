## 2. 用户已明确的产品与架构方向

### 2.1 协议与可信机制

- PACI Protocol 必须有实质性的链上可执行代码，不只是一份白皮书、承诺文案或单独登记的代码哈希。
- 在协议层实现适合确定性执行的记录承诺、权限/签名校验、追加版本、挑战回应及状态变更约束；具体实现需在协议窗口明确并测试。
- 原始劳工资料、合同、身份资料等不因协议上链而公开上链。链上执行与链下材料处理必须明确分离。
- 协议与 PACIscan 采用开源方向。现有仓库此前要求保持 Private；方向性同意开源不等于现在立即改变仓库可见性。正式公开前核对版本、许可证、敏感数据与授权。
- DOSSIVO 的正式证据卡必须实际经过对应的 PACIscan / Protocol 路径；不能仅挂品牌标志或贴一个合约地址。
- 用户可在 PACIscan 核验，也可通过正确网络的区块浏览器核对合约及相关记录。使用协议合约地址，不把普通钱包地址称为协议地址。
- 文案、技术规则、代码和测试应建立版本对应。文件摘要一致不等于文案与程序语义已经得到证明。

### 2.2 共同术语与证据边界

- 保留六式记账框架、AI Ledger、Jurisdiction Ledger 和 ENI（证据不膨胀原则）。
- 保留 Record / Explore / Verify / Challenge 四项能力。
- 分开记录：卡片是否忠实于来源、来源是否认证、来源是否独立、现实事实是否得到佐证、法律判断的依据与范围。
- 记录完整性通过不等于文件真实；文件签名通过不等于其内容真实或合法；平台自检不等于独立第三方佐证。
- 默认 PRIVATE，按授权提供 SHARED / PUBLIC。公开验证权不等于读取私人原件的权限。
- 错误或新信息通过追加更正处理；不可删除历史，不等于错误结论不可纠正。

### 2.3 首期产品重点与 JUG

- Agent Connect 与 Business Connect 优先；Wallet Scan 钱包扫描功能仍后置。
- 钱包扫描后置不等于协议链上可核验性无限期后置：二者是不同工作。
- DOSSIVO 是首个自有业务应用与测试场景，不计作已验证的独立外部客户。
- JUG 与 PACI Token 是不同对象。JUG 优惠不得改变核验结论、证据权限或独立性。
- 用户要求的回调方向：PACIscan 发生符合政策的优惠使用 → 通知 JUG 官网 → JUG 官网从对应用户优惠池扣减权益单位。
- 示例政策：一次 10 美元优惠消耗 1 个 JUG 链下优惠权益单位；库存不足允许记为负数。0.01 美元参考价不是这个扣减的兑换公式。
- JUG 官网是优惠库存的权威账本；重复回调不得重复扣减，退款用关联冲正；用户池映射、最终触发条件、重试与回执格式在接口契约中固定。
- 本项优惠先按链下机制实现，不把回调当作已经发行、转移或销毁链上代币。

## 3. 原始资料与待落实的审阅建议

主要原始资料：《Dossivo 证据交叉验证与异常标识规则规格 v0.1》（2026-11-05）。
原稿第 1 节将其定义为开发规则基线，并说明阈值为初始值；第 9 节提出 PACI 通用核心与 PACI-FLR Profile 的分层。

原稿及本对话的审阅意见必须分别保留。下列是审阅建议，尚不等同于用户逐条正式采纳、规则 v0.2 已发布或代码已经实现：

- 保留 L1/L2/L3 作为材料覆盖层级；避免未经校准的 1/3/5 可信权重。认证、独立性、覆盖范围和派生来源分别记录。
- 不用企业平均代发工资直接判断个人最低工资合规；先核对人员范围、期间、工资口径与适用规则。
- 不从高产量直接推出超时加班；不从正常能耗比率推出产量真实；共享同一输入的多个指标不等于独立佐证。
- H 类规则也应允许适用性异议与事实纠正，不把质疑规则等同于申请豁免法律。
- 资料不足不能显示全面无异常；待审解释和整改中不能显示问题已解决。
- 固定签核快照与实时最新状态分开；新状态不无痕改写旧卡片，也不自动扩大披露权限。
- 企业签核适用于企业确认的卡片；外部挑战和检查记录不能被被质疑企业拒签所阻断。
- CA 签名哈希上链与合约直接验证 CA 签名不是同一件事。算法、证书核验及信任桥接需另行设计。
- 直接决定正式 flag 与公开状态的规则应可独立检查；实验性闭源模型输出不得冒充完全可复现结论。
- 行业基准先解决可比性和样本独立性；所有初始阈值保留待校准标记，不直接永久固化为违法裁断。
- 最小协议验证路径应与正式卡片发布同步建设；复杂同行评分可后置。

进入协议窗口后，应先将用户明确要求、原稿要求、审阅建议及待决问题列为对照表，再形成版本化规范。涉及法律适用、规则效力或最新官方资料，须另行核查，不把此交接文件当作法律来源。

## 4. 分别管理版本，禁止凭名称推定兼容

至少分别记录以下版本：

- protocol_version：通用协议规范与链上执行规则；
- profile_version：例如 PACI-FLR 的领域规则；
- schema_version / api_version：数据格式及接口；
- paciscan_version：应用版本；
- dossivo_version：业务应用版本。

PACIscan 应用 v1.2 不是 PACI Protocol v1.2。
合约部署清单至少记录网络、chain_id、合约地址、部署交易、源码提交、编译配置、ABI 和公开源码验证结果；未部署时填“未部署”，不提供假地址。
通用协议窗口负责形成一个冻结的接口契约；另外两个窗口依据明确版本接入。不静默修改共享字段、枚举、摘要算法、签名消息或状态机。
