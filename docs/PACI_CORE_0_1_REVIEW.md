# paci-core 0.1 接入审查与最小整改清单

审查日期：2026-10-26。对象：用户提供的 `paci-core` 0.1.0 解压包，包括全部 `src/`、全部 `test/`、`ALIGNMENT.md`、`README.md` 和包配置。本文中的上游行号对应这次审查的原始代码，后续修改后应重新定位。

## 1. 接入决定

继续沿用并修复 paci-core，保持 Claude 负责 PACIscan、DOSSIVO 通过适配器对接的分工。已有实现具备可复用的数据结构、追加版本、摘要与正文分别承诺、基础访问控制、争议入口、Merkle 证明等能力。

目前可用于接口协作、合成材料演示和经过授权的最小记录试接。下述缺陷修复并验收前，不能直接承载真实敏感原件，也不能直接把 `SUPPORTED`、`independent_source_count`、汇总 `verification` 或离线证明的 `ok` 作为正式可信结论呈现。

整改按能力分别放行。DOSSIVO 的任务、材料目录、草稿、更正、业务撤回、企业回应和待同步状态可以继续开发，无需等待所有后续设施完成。

### 2.1 两份脚本是手动审计工具

两份脚本均采用以下核心目录选择顺序：

1. 第一个命令行参数；
2. 环境变量 `PACI_CORE_PATH`；
3. 脚本所在仓库旁的 `../alignment_review/paci-core`，对应本次解压布局。

显式参数和环境变量中的相对路径以当前工作目录解析；默认路径按脚本位置解析。脚本不依赖固定的临时目录或工作区绝对路径。需要 Node >= 22.6；使用 Node 22 时保留 `--experimental-strip-types`。

从 DOSSIVO 仓库根目录运行：

```bash
paci_review_node="${CODEX_PRIMARY_RUNTIME_NODE:-node}"
"$paci_review_node" --experimental-strip-types --no-warnings scripts/paci-adversarial-review.mjs ../alignment_review/paci-core
PACI_CORE_PATH=../alignment_review/paci-core "$paci_review_node" --experimental-strip-types --no-warnings scripts/paci-offline-audit.ts
```

也可在默认解压布局下省略目录，或传入其他本地副本。两个脚本均支持 `--help`。

**退出码的含义必须保留：**

- `0`：所有预设的**不安全现象仍能复现**，不是安全验收通过。
- `1`：至少一个探针行为变化或执行失败；可能是上游已修复、接口改变，也可能是运行错误，需要检查输出，不能自动判为修复成功。

每个场景输出 `expectedSafeBehavior` 与 `observed`。断言特意保留了“当前错误行为存在”的预期，用于核对已知基线。两份脚本位于 `scripts/`，**不加入默认 `test`、构建或发布门禁**。上游修复时，应把对应的安全预期写成正式回归测试，而不是要求本复现脚本继续全绿。

### 2.2 离线证明的信任锚控制

离线脚本首先从真实引擎取得运营者公钥，保存为 `opts.pinnedKeyPem`，验证合法原包确实成功且 `key_pinned: true`。全部篡改探针随后使用同一公钥，没有替换密钥，也没有信任攻击包自带的新公钥。

因此，以下离线缺陷不能用“接收者应该固定公钥”解释掉；固定公钥后它们仍然复现。未固定公钥时的低信任模式本身有既有警告，未被计入缺陷。

## 4. 十组必要问题

### R1. 返回对象可以直接改动内部状态

**位置：** `src/engine.ts:67、206、270、515、518–520`；`449–456` 还涉及嵌套输入引用。

**复现：**

- 登记后修改返回值 `r.content.secret`，再次查询得到新内容，版本仍为 1，日志仍只有原来的叶子。
- 修改返回的访问授权 `grantee` 和 `scope`，陌生人随即能读取原件。
- 修改 `openChallenge()` 返回值为 `status = 'REJECTED'`、`decided_by = 'operator'`，争议状态立即改变，历史仍只有 OPEN。

**安全预期：** 返回对象的修改应被拒绝或与内部状态隔离。任何有效状态变化必须经过授权方法和必要的追加记录；独立裁决不能由对象赋值绕过。

**最小修复：** 保存输入与返回输出时断开全部嵌套引用；注册配置对象也不能继续持有调用者可改的实例。DOSSIVO 先在适配器边界双向深拷贝，禁止页面和业务代码持有 engine 内部对象。

**阻断范围：** 真实数据及任何受控状态接入。

### R2. 幂等缓存保留已删除明文，重试跳过当前权限

**位置：** `src/engine.ts:388–400、547–558`；成员校验在首次执行回调的 `80` 行。

**复现：** 用固定键登记正文，调用 `eraseContent()` 后正常查询无正文；再用原键重试，仍返回旧正文和 `erased: false`。将调用者移出租户后，正常读取被拒绝，同键重试仍返回原正文。

**安全预期：** 每次重试都先检查当前权限；已删除内容不得由引擎自己的缓存重新返回。这个问题涉及内部留存，并非已下载副本无法撤回的既有边界。

**最小修复：** 缓存操作结果标识与必要元数据，而不是永久保存完整明文投影；按当前删除状态和权限重新生成响应，删除流程覆盖内部缓存。

**阻断范围：** 真实敏感数据及删除承诺。适配器可以阻止旧结果对外返回，但无法使 core 已有明文缓存自动满足删除承诺。

### R3. Link2 未绑定版本和实际页范围，无效日期被接受

**位置：** `src/types.ts:95–105`；`src/engine.ts:198–205、480–491`；相关原测试为 `test/conformance.test.ts:173–174`。

**复现：** `purpose` 写“version 1 page 1 only”，仍可读取正文中的其他页；记录更新后，旧授权自动读取版本 2。`expires_at: 'not-a-date'` 被接受，未触发过期拒绝。

**安全预期：** 未获准的版本和页不得被披露；无效授权日期应在写入时拒绝。自然语言目的不能代替执行权限。

**最小修复：** core 授权绑定精确版本、受控披露资源与有效期限；DOSSIVO 生成实际获准的裁剪或脱敏副本。不能把全文 PDF 的页码链接当作页级隔离。

**阻断范围：** 对外原件披露。SUMMARY/CONTENT 分离的现有正常路径可保留，但不能据此宣称页级 Link2 已完成。

### R4. 检查和 ENI 没有沿用记录读取权限

**位置：** `src/engine.ts:143–188、326–342`；`src/eni.ts:38–43、49`。

**复现：**

- 无法读取记录的 actor 自报 `FULL_CONTENT`、`THIRD_PARTY`，填写另一名已登记 reviewer 的 ID，即获得 `PASSED`、`independent: true`。
- 租户 A 的声明引用租户 B 的私密材料 ID，评估返回 B 的私密审核者名称并生成 SUPPORTED。
- 租户 B 添加一条自己的私密 `CONTRADICTS` 关系，可直接改变 A 的声明评估。

**安全预期：** 来源遍历、检查和结果披露使用明确授权集合；执行身份、可见材料和复核人关系来自可信上下文。未经审阅、不可访问的外部关系不应静默决定另一租户的结论。

**最小修复：** 为 `runCheck` 和评估依赖显式传递授权上下文；校验 actor 与 reviewer 的绑定；仅使用被授权、适用于目标声明的材料集合。DOSSIVO 可先隔离租户/区域实例并禁用未经授权的跨实例解析。

**边界：** `engine.ts` 已说明宿主负责身份认证，因此这不等于已证明存在公开 HTTP 攻击面。但宿主登录成功本身不能替代跨记录授权；不可把这些方法直接暴露给用户请求。

**阻断范围：** 跨租户部署和正式检查。

### R5. 来源名称被当作独立性，派生链和期间限制不足

**位置：** `src/eni.ts:22–32、48–84`；`src/engine.ts:179–182`。

**复现：** 同一租户上传两份材料，仅把 `attestor.name` 分别填写为不同名称，即得到 `independent_source_count: 2` 和佐证检查 PASSED。直接引用过期原件得到 EXPIRED，改为引用未设置到期日的派生材料则得到 SUPPORTED。只有一天的材料与全年声明发生重叠，也得到 SUPPORTED，没有提示未覆盖期间。

**安全预期：** 不同名称、不同来源根、控制主体不同和独立性已核实必须区分；根证据的适用限制应贯穿派生链；时间重叠不等于完整覆盖。

**最小修复：** 使用明确的来源身份与控制关系，无法核实独立性时保留未知。将关系链接视为材料关联，不自动解释为声明成立；呈现根证据时效、范围和未覆盖部分。

**阻断范围：** ENI 作为正式评估输出。材料登记、原始来源声明和去重分析可继续，不能用调用者填写的元数据制造独立核验。

### R6. 声明和证据引用没有真正绑定版本

**位置：** `src/engine.ts:179、332–338`；`src/eni.ts:16、22–25、37–41`。

**复现：** 声明版本 1 没有证据，版本 2 加入证据；请求检查版本 1，却使用最新版评估，将 PASSED 写入版本 1。证据引用为 `record_id@1` 时，`idOf()` 丢弃版本号并读取最新版，旧自述可被新版本的第三方来源声明替换。

**安全预期：** 请求哪个版本就检查哪个版本；任何改变输入集合的行为都形成新的评估，不能回写为旧版本结论。

**最小修复：** 评估入口接收确定的声明版本；关系和根证据使用确定版本的引用，不自动解析为 latest；检查记录绑定实际输入版本及规则版本。

**阻断范围：** 历史检查、复核及相关证明输出。

### R7. FAILED 检查被汇总忽略

**位置：** `src/engine.ts:586–595`。

**复现：** 完整性检查先 PASSED，正文发生修改后再次检查为 FAILED，查询仍返回 `verification: ["INTEGRITY_VERIFIED"]`。现有 G4 测试只检查单次 FAILED，没有验证最终状态投影。

**安全预期：** 保留历史成功记录，同时明确当前失败或冲突；旧成功不能覆盖新失败。

**最小修复：** 状态投影纳入失败及检查对象、方法、版本，避免跨对象或跨时点混成一个成功标签。适配器暂时显示逐项检查事实，不直接沿用该汇总数组。

**阻断范围：** 任何“已验证”状态对外展示。

### R8. 固定真实公钥后，离线证明仍接受篡改或虚假解释

**位置：** `src/verify.ts:23–35`；`src/log.ts:86–88`；`src/crypto.ts:10–13`；负索引检查涉及 `src/merkle.ts:54–67`。

**已复现：**

| 探针 | 当前结果 | 安全预期 |
| --- | --- | --- |
| 改 SUMMARY 包外层记录 ID 和版本 | `ok: true`，返回伪造身份 | 外层、叶子、披露正文身份必须一致，否则拒绝 |
| 改摘要并删除 `summary_salt` | `summary_matches: null`，总结果仍 true | 已披露对象缺验证材料应失败或明确为无效包 |
| 把 `witnessed`、`anchored` 改为 true | 签名仍有效，独立性警告消失 | 无真实见证证据时保留限制，不接受布尔标志冒充见证 |
| 改 JSON 自有 `__proto__` 字段内容 | `content_matches: true` | 所有受支持字段均须进入承诺，或统一拒绝该输入 |
| 将单叶证明的 `leaf_index` 改为 -1 | 总结果仍 true | 索引必须是范围内非负整数 |

`canonical()` 使用普通 `{}` 并按键赋值，导致自有 `__proto__` 字段从规范化结果中消失；这是规范化实现问题。上述结果不意味着 SHA-256、Ed25519 或正常 Merkle 算法被破解。

**最小修复：** 核验输入采用严格模式；身份与披露级别一致；需要的盐值和正文成对存在；规范化映射安全处理所有允许的键；拒绝非法索引。独立见证尚未实现时，验证器根据实际能力说明限制；只把布尔标志纳入运营者签名仍不能证明独立见证存在。

**阻断范围：** 离线证明包对外使用。不能只在 DOSSIVO 前端过滤，因为独立核验器本身也处理不可信的外部 JSON。

### R9. 通用登记绕过专项规则，时间和结果确认不足

**位置：** `src/engine.ts:110–138、405–443、453`。

**复现：**

- 直接登记 JURISDICTION 可接受 `BUYER_REQUIREMENT + PROHIBITED + is_legal_ruling: true`，绕过专用方法的限制。
- 直接登记 AI_ACTION 可接受空正文，没有授权、模型、工具或输入引用。
- INSTRUMENTED 接受 `occurred_at: 'not-a-date'`。
- 导入历史报告可显式把事件日期标为 SYSTEM_CLOCK。
- INSTRUMENTED + OUTCOME_CONFIRMED 只需一个 OUTCOME_OF 关系，目标不存在且没有对方证明也被接受。

**安全预期：** 所有写入和更正入口执行一致的记录类型校验；有效的采集授权不等于证明任意所填事件已被观测；系统接收时间不能替代历史事件时间。对方收到或接受必须有与对应动作和接收方绑定的依据。

**最小修复：** 把专项约束下沉至共同验证边界；INSTRUMENTED 由受控采集器形成；验证日期有效性、授权区间、动作目标与结果依据。适配器不允许前端自行指定可信执行来源。

**阻断范围：** 正式来源、法域分类、AI 执行和接收方接受状态。ALIGNMENT 的 C1、C4、C5 目前只在部分正常路径成立。

### R10. 外部质疑者无法读取自己创建的质疑和回应

**位置：** `src/engine.ts:251–270、318–321`。

**复现：** 买家有目标记录 SUMMARY 权限，成功创建质疑；企业作出回应后，买家 `getChallenge()` 得到 NOT_FOUND。新质疑继承了 PRIVATE 可见性，但参与人没有对应读取权限。

**安全预期：** 质疑参与人能读取自己参与范围内的质疑、回应和处理历史，同时不因此获得原件或其他私密证据权限。

**最小修复：** 明确参与人权限与证据披露权限的分别授予和撤销规则；原记录、质疑、回应与转移记录的权限需要一致闭环。

**阻断范围：** 外部 Challenge 闭环上线。无独立复核人时可以停留在 UNDER_REVIEW，但不妨碍企业回应、追加更正、业务撤回或质疑者撤回。

## 5. 应保留的规则与可后续增强

### 5.1 独立裁决规则保留

同一主体运营 DOSSIVO 和 PACIscan 时，平台内部检查不能冒充独立第三方审查。UPHELD / REJECTED / PARTIALLY_UPHELD 仍应由符合资格、非当事方、独立于运营者的复核人作出；上诉应使用不同复核人。R1 的可变对象旁路必须修复。

企业的业务更正、业务撤回、补充材料，以及质疑者撤回质疑，是分别授权的动作。它们可以独立推进，不能因等待独立裁决而冻结；业务状态不得写成 PACI 已经裁决。

### 5.2 区域日志的实际边界

当前代码在一个内存进程中按区域分别维护日志。原有区域测试证明逻辑分流，不能证明物理驻留、跨区域访问限制或完整跨境合规。

复现脚本还展示：通过受信配置方法 `registerTenant()` 以同一租户 ID 覆盖区域后，后续版本会进入新区域日志。该场景用于配置与迁移验收，不描述为任意外部攻击。宿主应禁止无迁移流程的改区，并分别验证存储、执行、模型、运维、日志和备份的实际路径。

### 5.3 不需要阻挡当前业务开发的后续设施

- 独立见证和外部锚定可以后续建设；在尚未实现时，导出及验证器必须如实说明，且限制不能由包内标志消除。
- 公开核验页面、持久化适配器和 HTTP 服务分别按实际发布范围建设。内存参考核心不能被描述为已具备生产持久化。
- 自动查明全部来源的所有权与控制关系可以逐步完善；当前可采用“独立性未知/待核实”，不能用名称计数补足结论。
- 原件客户侧执行、密钥托管和 DOSSIVO 业务 AI 属明确接口下的后续实现。paci-core 的证据规则不能替代 OCR、抽取、翻译或业务推理。

## 6. DOSSIVO 适配器应固定的最小契约

1. 身份、租户、执行者和实际可见材料由服务端确定；不接受前端自报独立性或执行环境即升级可信度。
2. core 输入输出双向深拷贝，内部对象不进入页面状态；核心配置入口只向受控宿主开放。
3. 每次查询、缓存命中、重试和导出重新鉴权；已删除正文不由幂等结果恢复。
4. 原件与敏感衍生数据留在已批准执行边界；向 PACI 提交获准的最小记录，不能把授权摘要等同于无敏感性。
5. Link1 和 Link2 分别授权；Link2 指向实际受控版本和页资源，旧授权不自动开放新版本。
6. 检查绑定实际输入、证据和规则版本；失败、未知、材料未见和来源未核实均保持可见。
7. 离线验证执行严格结构、身份、承诺与范围检查，固定正确公钥，并单独说明见证和日志一致性限制。
8. PACI 不可用时保存草稿、操作标识和待同步状态；未完成检查不得借旧结果显示已验证。
9. 质疑、回应、更正与业务撤回按各自权限执行；独立裁决要求保留。

这些是接入契约与修复验收方向，本文不声称 DOSSIVO 现有适配器已经全部实现。正式回归测试应针对以上真实边界，而不是只检查函数存在或重复实现细节。
